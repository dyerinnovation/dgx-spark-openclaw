## Research Complete - 2026-02-09

## 1. Official Docker Compose (openclaw/openclaw)

### Gateway Token
- **Generated during `docker-setup.sh`** via `openssl rand -hex 32` (falls back to python3)
- Stored in `.env` file as `OPENCLAW_GATEWAY_TOKEN`
- Injected as environment variable into both gateway and cli containers

### openclaw.json Management
- **Volume mount**: `${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw` maps host directory directly
- Config is created during the interactive onboarding process (`docker-setup.sh` runs the gateway with onboarding flags)
- No ConfigMap equivalent; it lives on the host filesystem

### Entrypoint / CMD
- **Dockerfile CMD**: `node openclaw.mjs gateway --allow-unconfigured`
- **docker-compose override**: `node dist/index.js gateway --bind ${OPENCLAW_GATEWAY_BIND:-lan} --port 18789`
- CLI service uses: `node dist/index.js` as entrypoint (interactive)

### Slack Configuration
- Configured interactively during `docker-setup.sh` onboarding
- The script optionally runs channel configuration (WhatsApp, Telegram, Discord, Slack)
- Not pre-configured in any config file

### Ports
- Gateway: 18789 (configurable via `OPENCLAW_GATEWAY_PORT`)
- Bridge: 18790 (configurable via `OPENCLAW_BRIDGE_PORT`)

### Resources
- No resource limits defined (bare Docker)

### Image
- Builds from source: `node:22-bookworm` base, installs Bun + pnpm, builds from repo
- Runs as non-root `node` user
- Build arg `OPENCLAW_DOCKER_APT_PACKAGES` for extra system packages

### Key Config Example
```yaml
# .env
OPENCLAW_IMAGE=openclaw:local
OPENCLAW_CONFIG_DIR=~/.openclaw
OPENCLAW_WORKSPACE_DIR=~/.openclaw/workspace
OPENCLAW_GATEWAY_PORT=18789
OPENCLAW_BRIDGE_PORT=18790
OPENCLAW_GATEWAY_BIND=lan
OPENCLAW_GATEWAY_TOKEN=<32-byte-hex>
```

## 2. serhanekicii/openclaw-helm (v1.3.11)

### Architecture
- **Based on bjw-s app-template v4.6.2** (library chart pattern)
- Only file in `templates/` is `NOTES.txt` -- all K8s resources are generated by the library chart from values.yaml
- Kubernetes >= 1.26.0 required

### Gateway Token
- Appears to be set in values.yaml or provided at install time
- NOTES.txt instructs user to enter the token in the gateway web UI after port-forwarding
- Device pairing done via `kubectl exec` running Node.js device management scripts

### openclaw.json Management
- **ConfigMap-based** via the app-template library
- Init container `init-config` merges Helm values with any persisted config (supports `merge` or `overwrite` mode)
- Config stored on a **5Gi PVC** at `/home/node/.openclaw`
- Init container runs as root (UID 0) for directory setup, then main container runs as non-root

### Init Containers
1. **init-config**: Node.js JSON processing to merge ConfigMap values into persisted openclaw.json (strips JSON5 comments, preserves URLs)
2. **init-skills**: Declaratively installs ClawHub skills; supports runtime deps (Python, Go)

### Slack Configuration
- Configured via `openclaw.configOverrides` in values.yaml which gets merged into openclaw.json
- No interactive onboarding; everything is declarative

### Resources
- **Main container**: 200m-2000m CPU, 512Mi-2Gi memory
- **Chromium sidecar**: 100m-1000m CPU, 256Mi-1Gi memory
- TCP health probes on all containers

### Security
- Non-root execution enforced (fsGroup: 1000)
- Read-only root filesystem
- All Linux capabilities dropped
- emptyDir for /tmp
- Optional NetworkPolicy support

### Image
- Uses **official image**: `ghcr.io/openclaw/openclaw:2026.2.6`
- Optional Chromium sidecar: `zenika/alpine-chrome:124`

### Default Agent Config (from values.yaml)
```json
{
  "agents": {
    "defaults": {
      "model": "anthropic/claude-opus-4-6",
      "timeoutSeconds": 600,
      "thinkingDefault": "high"
    }
  },
  "gateway": {
    "mode": "local"
  }
}
```

### "Doctor Warning" Handling
- Since config is declarative via ConfigMap, Slack would need to be pre-configured in `configOverrides`
- The "configured but not enabled" warning likely persists until the Slack bot token is active and the channel is actually connected

### Key Values Example
```yaml
openclaw:
  bind: lan
  configMode: merge  # or overwrite for strict GitOps

  config:
    agents:
      defaults:
        model: "anthropic/claude-opus-4-6"
        timeoutSeconds: 600

  configOverrides: {}  # Additional JSON merged into openclaw.json

persistence:
  data:
    enabled: true
    size: 5Gi
    accessMode: ReadWriteOnce

chromium:
  enabled: false  # Enable for browser automation
```

## 3. chrisbattarbee/openclaw-helm (v0.1.7)

### Architecture
- **Standalone templates** (no library chart dependency)
- Standard Helm chart with explicit template files: deployment, service, configmap, secret, ingress, pvc, serviceaccount
- More transparent/readable than the app-template approach

### Gateway Token
- **Auto-generated if not provided**: `randAlphaNum 32` in secret.yaml template
- Can be pre-set via `values.yaml` or `--set` flag
- Stored in a Kubernetes Secret, injected as env var
- Supports `existingSecret` to reference a pre-created secret

### openclaw.json Management
- **ConfigMap** generated from values.yaml
- Deployment includes an **init-config container** that merges ConfigMap values with persisted config (same merge pattern as serhanekicii)
- Optional **init-skills container** for ClawHub skill installation
- Config persisted on PVC (5Gi default)

### Init Containers
1. **init-config**: Merges Helm ConfigMap values into persisted config; supports merge mode
2. **init-skills**: Conditional skill installation

### Slack Configuration
- Via `openclaw.configOverrides` in values.yaml (declarative)
- Example pattern:
```yaml
openclaw:
  configOverrides:
    channels:
      slack:
        botToken: "xoxb-..."
        appToken: "xapp-..."
        signingSecret: "..."
```

### Entrypoint / CMD
- Main container command: `node openclaw.mjs gateway --bind <bind> --port 18789`
- Configurable bind address (lan/localhost)

### Resources
- Similar to serhanekicii: configurable CPU/memory requests and limits
- Default model: `anthropic/claude-sonnet-4-20250514` (Sonnet, not Opus)
- Thinking mode options: low, high, off

### Security
- Non-root (UID 1000)
- Read-only root filesystem option
- RuntimeDefault seccomp profile

### Ports
- Gateway: 18789 (WebSocket)
- Canvas: 18793 (HTTP)

### Image
- Uses **official image**: `ghcr.io/openclaw/openclaw:2026.2.6`
- Optional Chromium sidecar

### Health Probes
- Liveness, readiness, startup probes (TCP socket)
- Configurable thresholds and delays

### Key Values Example
```yaml
image:
  repository: ghcr.io/openclaw/openclaw
  tag: "2026.2.6"

openclaw:
  bind: lan
  config:
    agents:
      defaults:
        model: "anthropic/claude-sonnet-4-20250514"
        timeoutSeconds: 600
        thinkingDefault: "high"

credentials:
  anthropicApiKey: ""
  gatewayToken: ""  # Auto-generated if empty
  existingSecret: ""  # Use pre-created secret

persistence:
  enabled: true
  size: 5Gi

chromium:
  enabled: false

ingress:
  enabled: false
```

## Recommendation for DGX Spark Deployment

**chrisbattarbee/openclaw-helm is the best fit** for the following reasons:

1. **Transparent templates** - You can read and modify every K8s resource directly, unlike the bjw-s app-template approach which hides everything behind values conventions
2. **Auto-generated gateway token** - The `randAlphaNum 32` in secret.yaml means you don't need to pre-generate tokens; just deploy and it works
3. **existingSecret support** - You can create your own Secret with all credentials and reference it, which fits the `.env` + Helm `--set` workflow already in CLAUDE.md
4. **Standard Helm patterns** - deployment.yaml, service.yaml, etc. are easy to extend for your custom needs (e.g., adding GPU resources, custom init containers for Qwen3)
5. **Declarative Slack config** - Via `configOverrides` in values, no interactive onboarding needed

### Concrete Next Steps
1. Use chrisbattarbee/openclaw-helm as reference for your `charts/openclaw/` chart
2. Add gateway token to your Secret (or let it auto-generate)
3. Configure Slack via `configOverrides`:
```yaml
openclaw:
  configOverrides:
    channels:
      slack:
        botToken: "${SLACK_BOT_TOKEN}"
        appToken: "${SLACK_APP_TOKEN}"
```
4. Set model to `anthropic/claude-opus-4-6` in config
5. Add PVC for persistence on the DGX Spark
